## Motor: Claude pela API (desde 12/11/2026), fora da cota do Max
- O Rodrigo recebe **US$ 100/mês de créditos da API Anthropic** junto com o Max (valem para API, Agent SDK, Managed Agents e Playground; **não** para sessões do Claude Code). As rotinas automáticas usam esses créditos: `_rotina_claude.sh` chama **`rotina_api.py`** (Agent SDK em Python: mesmas ferramentas do Claude Code, mesmo prompt, mesmo cwd, `bypassPermissions`, CLAUDE.md do projeto carregado) com a chave `~/.segredos/anthropic/rotinas.env`, passada só ao processo filho. O script confere no `init` que a autenticação é a chave (`apiKeySource=ANTHROPIC_API_KEY`) e aborta se não for.
- **Modelo e orçamento por execução:** tendências sonnet (US$ 4), palavras-chave sonnet (US$ 3), métricas sonnet (US$ 1,5); `MODELO=` e `ORCAMENTO=` sobrescrevem. Teto mensal do grupo rotinas+garimpo: **US$ 50** (qa 25, dev 25; total 100; desde 14/11/2026) (`tools/anthropic_api.py`; a rotina não começa se o gasto do mês + orçamento passar).
- **Falha da API → fallback para o Max (12/11/2026):** erro HTTP/5xx/overload persistente (após os retries do SDK), chave inválida, crédito esgotado ou teto mensal do grupo: `rotina_api.py` (e `job_api.py`) registram em `ops.event_log` e **caem 1× para o plano Max** (`claude -p` via `claude_run.sh`, `ANTHROPIC_API_KEY` removida; módulo `tools/fallback_max.py`) com o mesmo prompt; sem loop. Orçamento da execução estourado e timeout não acionam fallback. `garimpo_batch.py` (Batch API não existe no Max) e `preqa_visual.py` registram e seguem sem bloquear (pré-QA escreve "pré-QA visual não rodou" no `PREQA-visual.md`; a conferência manual vale). O resumo/Telegram ganha uma linha ⚠ quando houve aviso/erro nas últimas 48 h. Na mão com a API fora: `MOTOR=claude-code tools/rotinas/<rotina>.sh`.
- **Eventos (`ops.event_log`, schema `ops`, DDL `tools/db/schema_ops.sql`):** colunas `id, ts, origem, tipo, severidade (info/aviso/erro), mensagem, detalhes jsonb, ref`; tipos `api_erro, api_credito, teto_aviso (≥ 80%, 1× por grupo/mês), teto_atingido, fallback_max, fallback_ok, fallback_falhou, info`. Detalhes nunca levam segredo (filtro em `event_log.py`). Consultar: `psql -d vida -c "select ts, origem, tipo, severidade, mensagem from ops.event_log order by ts desc limit 20"`. Registrar: Python `from event_log import registrar`; bash `tools/evento.sh <origem> <tipo> <info|aviso|erro> "<msg>" [ref]`. Testar o fallback sem tocar nas chaves reais: `FABRICA_CHAVE_ARQUIVO=<.env falso>` (chave inválida) ou `FABRICA_TETO_TESTE=0.0001` (teto artificial).
- **Custo real** em `financas.consumo` (fornecedor `Anthropic API`, servico `rotina:<rotina>`) e uma linha em `youtube.execucoes_claude` (modelo `api:<modelo>`). Saldo do mês: `select * from financas.saldo_pre_pago where fornecedor='Anthropic API'` (o crédito de US$ 100 é lançado todo mês em `financas.lancamentos`, `valor_brl` 0).
- **Estimativa (12/11/2026, Sonnet 5.5 a US$ 2/10 por MTok):** métricas ~US$ 0,20–0,40, tendências ~US$ 0,15 (teste) a ~0,60 (completo), palavras-chave ~US$ 0,50 por execução → **~US$ 8–12/mês** nas rotinas; garimpo em lote ~US$ 0,5–1,1 por rodada → ~US$ 5–10/mês. Total ~US$ 15–20 de US$ 65.

## Como funcionam `metricas.sh`, `tendencias.sh`, `palavras-chave.sh` e `reembalagem.sh`
- Todos chamam `_rotina_claude.sh <rotina>`, que monta o prompt de `prompts/<rotina>.md` (troca `{{DATA}}`, `{{SUF}}` (`-teste` no teste), `{{MODO}}`, `{{RELATORIO}}`, `{{RESUMO}}`) e roda `rotina_api.py --rotina <rotina>` (seção acima; trava anti-duplicação compartilhada com o `claude_run`, registro em `youtube.execucoes_claude` e `financas.consumo`). Até 11/11/2026 rodavam `tools/claude_run.sh --etapa <rotina>` (claude -p, cota do Max).
- Saídas em `~/workspace/relatorios/<rotina>/`: `<data>.md` (relatório completo), `<data>-resumo.txt` (resumo executivo de 5–10 linhas) e `logs/`. O Claude também copia o relatório para `pesquisa/<rotina>/` e commita os aprendizados (na bíblia do canal, `canais/<slug>/biblia/`, ou em `conhecimento/` se forem gerais) (o push vem do `git-diario.sh`).
- **Entrega no Telegram:** `hermes send --to telegram` manda o resumo + o relatório anexado (`MEDIA:`) para o home channel do bot do default. Esse comando usa o token do `~/.hermes/.env` direto, **sem LLM e sem o gateway rodando**. Se o envio falhar, fica só o arquivo em `relatorios/`.
- Opções: `--teste` (tendências: não roda `trends.py`, reaproveita o último garimpo, no máximo 2 vídeos e 1 busca; palavras-chave: `keywords.py --teste`, sem a–z, 3 termos, ≤ 303 un., não grava no banco; arquivos com sufixo `-teste`) e `--sem-telegram`. `TIMEOUT=<s>` muda o limite (padrão 5400 s).
- Rodar na mão: `tools/rotinas/metricas.sh` ou `systemctl --user start fabrica-metricas.service`. Ver: `systemctl --user list-timers | grep fabrica`, `journalctl --user -u fabrica-metricas`.

## Instalação dos timers
Os unit files ficam em `systemd/` (versionados) e são symlinks em `~/.config/systemd/user/`:
```bash
cd ~/workspace/fabrica-youtube/tools/rotinas/systemd
for f in fabrica-*; do ln -sf "$PWD/$f" ~/.config/systemd/user/$f; done
systemctl --user daemon-reload
systemctl --user enable --now fabrica-analytics.timer fabrica-metricas.timer fabrica-tendencias.timer fabrica-palavras-chave.timer fabrica-reembalagem.timer
```

## Reembalagem semanal (padrão Lutz, desde 14/11/2026)
Pedido do Rodrigo: toda semana olhar os vídeos publicados e aplicar os 3 padrões: **1)** CTR baixo + retenção alta → trocar título e thumb (único caso com proposta); **2)** CTR alto + retenção baixa → lição de conteúdo para os próximos roteiros; **3)** CTR e retenção altos + views baixas → temas mais amplos. Escopo: historia-ptbr, dossie-es, em-relevo, lugares-guerra-en; vídeos longos públicos com ≥ 7 dias.
- **Etapa sem IA** (`reembalagem.py preparar`): baixa a Reporting API (`reporting.py`), fotografa título e thumb no ar (`youtube.embalagem_snapshot`: Data API + sha1 da imagem via WARP), escolhe a **fonte** por canal (Reporting API se cobrir ≥ 21 dos 28 dias; senão o export do Studio mais recente em `youtube.studio_video`, se tiver ≤ 10 dias; senão a API parcial, marcada), mede a retenção (Studio ou Analytics API na mesma janela), classifica e aplica o ciclo de vida. Grava `~/workspace/relatorios/reembalagem/dados/<data>[-teste].{json,md}` (inclui a validação Studio × Analytics × Reporting).
- **Limiares** (relativos ao canal; fixos em `reembalagem.py`, repetidos em `prompts/reembalagem.md`): mínimo 300 impressões; referência = mediana do canal (≥ 3 vídeos com dados; senão CTR 5% / ret. 42%); CTR baixo < 0,8× ref ou < 4%; retenção alta ≥ 0,9× ref ou ≥ 50%; retenção baixa < 0,85× ref e < 40%; views baixas = impressões/dia < 0,5× a mediana do canal. Prioridade do padrão 1 = cliques perdidos (impressões × (max(ref, 4%) − CTR)); máx. 5 propostas por semana.
- **Agente** (`prompts/reembalagem.md`, sonnet, US$ 4): para cada candidato, momentos do vídeo com timestamp da `legendas.srt`, pesquisa com `skills/embalagem/scripts/pesquisa_embalagem.py` (sem `search.list`), `PROPOSTA.md` (T1/T2 de padrões diferentes + conceito de thumb), **crivo independente** (Task opus, regra de `skills/embalagem/CRIVO.md` em modo reembalagem: promessa paga conferida na legenda; máx. 2 rodadas). Só o aprovado vai na mensagem e é registrado (`reembalagem.py registrar`). Saídas: `relatorios/reembalagem/<data>.md` + `-resumo.txt` (Telegram) e cópia em `pesquisa/reembalagem/<data>/` (commit).
- **Controle de validade** (`youtube.reembalagem`, DDL `tools/db/schema_reembalagem.sql`): sugerido e não aplicado → 4 semanas sem nova sugestão, com 1 lembrete de 1 linha; troca detectada (título no ar ≠ título da sugestão, ou sha1 da thumb diferente) ou marcada na mão (`reembalagem.py marcar --youtube-id X --aplicado AAAA-MM-DD`) → **quarentena de 21 dias** → antes × depois com o mesmo nº de dias (Reporting API) → **melhorou** (CTR ≥ 1,15× e +0,5 pp com ≥ 300 impressões: encerrado, volta só se o CTR cair < 0,7×) ou **não melhorou** (mais 1 tentativa com padrão diferente; teto 2; a 2ª sem melhora = `embalagem_nao_e_problema`, sai para sempre). Vídeo com > 90 dias e < 100 impressões/semana sai do escopo (envelhecido). Placar: `reembalagem.py placar`.
- **Lote de 14/11/2026:** os 15 reembalados (`pesquisa/reembalagem-2026-11-14/`) foram registrados como `aplicado` em 14/11 (`reembalagem.py semear-lote`; "antes" = Studio 28 d até 13/11) e ficam em quarentena até 05/12, quando a rotina mede o antes × depois. Na foto de 14/11 (14:45), 11 tinham o T1 novo no ar; Cosa Nostra e Masones só mudaram as maiúsculas (sem o subtítulo proposto); El Niño e Sul seguiam com o título antigo (talvez em "Testar e comparar", que a detecção por título não enxerga); o da KGB termina com "(" (sobra do "(64)" colado): conferir no Studio.
- **Limitação:** durante um "Testar e comparar" a Data API devolve um só título/thumb; se a troca não for detectada, marque na mão.
- Na mão: `tools/rotinas/reembalagem.sh [--teste] [--sem-telegram]` (`--teste`: não grava em `youtube.reembalagem`, 1 vídeo, `LIMITE=2` para 2; se não houver candidato elegível, simula com um vídeo em quarentena) ou `systemctl --user start fabrica-reembalagem.service`.
